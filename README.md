# autofilling_tabel
Репозиторий для сервиса автоматического заполнения клиентов в табеле.

## Как пользоваться

Открой `index.html` в браузере (двойным кликом, сервер не нужен):

1. Загрузи табель импорта (`Табель №АМ и для склада.xlsx`) и/или табель Голландии (`Табель №АМ г для склада.xlsx`).
2. Загрузи справочник `Клиенты и маркировки - общий.xlsx`.
3. Нажми «Заполнить табеля» и посмотри консоль.
4. Скачай результат: файлы сохранятся с припиской `(заполнен)`.

Файлы обрабатываются прямо в браузере и никуда не отправляются.

## Правила заполнения

- **Импорт**: верхняя таблица не трогается, заполняются все нижние таблицы-разбивки. Справочник — лист `ИМПОРТ`.
- **Голландия**: заполняются обе таблицы (Холод и Тепло). Справочник — лист `ГОЛЛАНДИЯ`.
  Если столбец склада подписан не «Склад» (например «AA»), склад пишется в столбец сразу после «Комментарии».
- Маркировки сравниваются строго, но без учёта регистра и пробелов; кириллические буквы-двойники латиницы (А, В, Е, К, М, Н, О, Р, С, Т, У, Х) считаются латинскими.
- Если маркировка целиком не нашлась, отбрасывается префикс `b-` / `B ` / `QW ` / `QW.` / `FLT ` (только с разделителем, «QWERTY» не пострадает) и поиск повторяется.
- Вписываются только пустые ячейки «№ Клиента», «Клиент», «Склад». Уже вписанное не перезаписывается:
  - стоит номер, и он не совпадает со справочником → строка не меняется, в консоли ошибка;
  - стоит только имя → сверяется с именем клиента по найденному номеру; не соотносится → строка не меняется.
- Ничего не вставляется (только предупреждение в консоли), если:
  - маркировка есть у нескольких клиентов с разными номерами;
  - нашлось только похожее совпадение: часть ячейки, где записано несколько маркировок, или запись в справочнике с префиксом (`B-QW.MOG001` для `QW MOG001`);
  - у клиента в справочнике нет номера.
- Склад: если в справочнике указано несколько («Котельники, Можайск»), берётся первый; Можайск при вставке всегда заменяется на Химки.
- Листы с крупными клиентами (ДЖАЗ, МФ) пока не используются.

Таблицы в табеле ищутся по строке заголовков (`№ Клиента`, `Клиент`, `Маркировка`), так что сдвиг строк или столбцов не мешает.
Файл правится на уровне XML: форматирование, «умные таблицы», формулы и прочее остаются как были;
при открытии Excel пересчитает формулы.

## Разработка

```bash
npm install
npm run build       # src/*.ts → index.html (один самодостаточный файл)
npm run typecheck
# прогон в Node на реальных файлах:
npm run selftest -- "Клиенты и маркировки - общий.xlsx" "import|Табель и.xlsx|out_i.xlsx" "holland|Табель г.xlsx|out_g.xlsx"
```

Структура:

- `src/xlsx/` — чтение и точечная запись xlsx (fflate + DOMParser);
- `src/normalize.ts` — нормализация маркировок, префиксы, сравнение имён;
- `src/reference.ts` — разбор справочника и поиск по маркировке;
- `src/tabel.ts` — поиск таблиц в табеле и заполнение строк;
- `src/main.ts`, `src/index.html` — интерфейс.

## Публикация (GitHub Pages)

Сервис публикуется автоматически workflow `.github/workflows/pages.yml`: при каждом пуше в `main`
GitHub проверяет типы, собирает `index.html` и выкладывает его на Pages (исходники на сайт не попадают).

Один раз нужно включить: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Адрес: `https://<логин>.github.io/autofilling_tabel/`. Ход сборки — во вкладке **Actions**.

`index.html` в корне репозитория оставлен для локального запуска двойным кликом (его обновляет `npm run build`).

⚠️ Не коммить табели и «Клиенты и маркировки»: в них данные клиентов.
